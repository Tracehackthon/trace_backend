## 2026-09-15 S1 实施切片

本轮已落地 S1 的**执行切片**，不是整个 S1 出口已经完成：

- `apps/agent/runtime.mjs` 定义 provider-neutral executor 与 run-scoped tool bridge；`service.mjs` 不再固定调用 Codex。
- `profiles.mjs` 从服务端文件加载 `codex / model / agent` profile，按 id/owner/version/revision 固定每次运行；Web 只能选择 `profileId`。
- `model.mjs` 实现 OpenAI-compatible 非流式模型协议和最多 12 次受限工具循环；`external-agent.mjs` 实现 `trace-external-agent-v1` 的 check/start/tool_result/completed/cancel。
- 凭据只从 profile 声明的服务端环境变量读取，不进入 capabilities、事件、运行记录或模型上下文；远程 endpoint 固定、HTTPS（loopback 测试除外）、不跟随 redirect、响应有上限。Codex 子进程额外移除其他 profile 的凭据变量。
- 合成 HTTP provider 已在**没有 Codex 可执行文件和登录**的路径覆盖模型闭环、完整 Agent 闭环、工具实际读取、引用、取消、profile 漂移、非法工具/配置与凭据隐藏。

仍未完成 S1 出口中的两库备份/恢复与归档、强杀后的实际恢复副本演练、真实选定远程模型验证、目标部署身份/队列/多 worker 隔离。因此不能把“adapter 已实现”写成远程生产服务已开放。

## 按闸门推进，不按文档数量推进

### S0 · 收敛入口（本轮）

**交付**：仓库 README 只解释角色与启动；产品介绍单独保留；API 随实现；历史原型退出当前事实。增加单一启动入口，校验端口/数据位置，不接管旧服务。

**出口**：首次运行不需学习 MCP 或复制多组环境变量；原服务数据位置不变；开关、端口冲突和隔离启动有测试；链接可用。文档整理不算生产上线。

### S1 · 独立执行底座与可靠运行（下一阶段优先）

**非 Codex 最小闭环已经完成**：`backend.mjs` 不再固定创建 Codex，`http.mjs` 返回通用能力与安全 profile 描述；服务端 profile、模型 adapter、受限工具循环和完整外部 Agent adapter 已接入同一运行/事件/版本协议。当前通过的是合成 HTTP provider，不先假定真实供应方全部兼容。

**独立性验收**：在没有 Codex 可执行文件、个人登录、Plugin 和 hooks 的环境中，用模拟模型跑通“HTTP → Runtime → 上下文工具 → 最终候选 → SSE 重放/取消”；检查超步数、伪造工具、越权 profile、配置版本变化和迟到输出。确定首个供应方后，用合成数据补真实模型验证；模拟测试不能证明真实连接。

| 工作项 | 负责边界 | 验收条件 |
| --- | --- | --- |
| 执行抽象与模型循环 | AgentService / Trace Agent Runtime / adapters | 同一产品任务可选择已授权 profile；模型与完整 Agent 服务分开适配；工具、流式、输出与取消能力明确声明，不静默降级或切换 |
| 配置与凭据 | 服务端配置 / 身份边界 | profile 有归属与版本；凭据不进入浏览器、模型或事件；固定每次运行的配置身份，撤权可阻止继续执行 |
| 服务生命周期与健康 | HTTP 宿主 / 后端 | 启动失败不留锁；端口竞争、正常停止、崩溃恢复、磁盘写失败不损坏产品数据；健康响应区分进程、存储、CLI 与模型检查 |
| 版本与上下文 | 产品领域 + AgentService | 引入对象 generation / revision 前先保留保守 CAS；跨事项编辑不误接候选，删除重建同 ID 和 fresh 切换必须拒绝旧结果 |
| 运行维护 | AgentStore / WebStore | 两库可恢复备份、归档上限、错误定位；强杀后未完成任务标 interrupted、不自动再次计费；恢复副本能重放业务读取 |
| Codex 兼容 | CodexAdapter | 维护通过验证的版本范围；升级需 wire 边界负例及合成数据 live 闭环；不因报错删除隔离校验 |

**出口**：从空库和既有库副本都完成“启动 → 生成 → 断线续读 → 取消/崩溃恢复 → 重启 → 恢复备份”。产物版本、配置摘要、实际测试对象对应，不能只附源码测试截图。

**可推迟**：目录抽包不是先决条件。若抽出产品 domain，保留兼容导出与 HTTP 契约，逐项迁移，禁止同时改库 schema、换协议和重做页面。

### S2 · 可让 Web 正式接入的业务闭环

**后端交付**：真实 `revision_candidate` 的显式采用命令；绑定 run/事项/选区/版本，幂等回执、冲突拒绝、撤销记录。不允许通过旧原型假候选或客户端提交最终 host 绕过。

**接入交付**：保持一份 API 协议，补最小调用客户端/fixture；对提交丢响应、SSE 重连、stale、取消、错误、重新发起明确状态。请求 ID 不因重试改变，不隐式换模型。

**出口**：无需改现有页面也能通过 HTTP 完成“产品命令建事项 → 真实生成 → 用户确认命令 → 正式理解修订 → 回执查询/撤销”；仅保存结果时正文不变。然后将契约与同一固定后端版本交给 Web 任务做展示验收。页面接入是后续依赖，不能写作本轮已完成。

**外部来源**：知乎/全网检索作为独立 provider，显式 opt-in；来源事实与模型解释分开。OAuth 凭证不得流入模型输入、通用事件或前端配置；真实查询、返回来源、用户选择、确认关联逐步验收，不用 adapter 存在替代端到端。

### S3 · 可复现的服务交付与小范围试用

**交付单元分别命名**：独立产品/Agent 服务（远程主路径）；可选本机服务包；Codex Plugin/runtime 包。可以共用领域代码，但不能把其中一个包的测试当另一个的验收。远程交付须先满足下方 S4 的身份与隔离条件，不因完成容器构建就开放公网。

1. 从已确认的固定来源构建，采用输入白名单，排除 `.trace`、临时库、私人配置、测试输出、无关 Electron 依赖与设计原件；保留实际所需资源和许可。
2. manifest 记录来源 revision/必要变更身份、运行版本、协议与兼容范围、文件 hash、目标平台；当前 manifest 不足的字段需补齐。
3. 在干净目录/目标机器运行**实际包**：安装、首次启动、生成/回流、升级、备份恢复、失败回退；修复既有发行安装失败，不能跳过后称发布通过。
4. 明确托管 CI 权限、触发路径与两类产物的检查，未经授权不改公共工作流、签名或正式发布配置。

**出口**：实际分发包与验收包 hash 一致，且业务闭环在该包上通过；一次小范围试用能在不丢内容的情况下升级并退回兼容版本。版本文字或上传成功不是业务验收。

### S4 · 远程身份与运行隔离（远程交付前必需）

| 路线 | 必须补齐 | 适合的前提 |
| --- | --- | --- |
| 独立远程服务（已选方向） | 账号/租户隔离、profile 授权、密钥与模型费用归属、受控 worker、队列/背压、出站限制、数据删除、审计与恢复 | 无本机 Codex 依赖，Web 经 Trace 后端使用已配置 Agent |
| 本机连接器（可选后续） | 配对与撤销、设备身份、短期凭据、精确来源约束、显式数据导入 | 只有需要远程页面调用用户自己的本机能力时才实施；不是远程版前置条件 |

不能通过改监听地址或加 `CORS:*` 替代认证。产品库为权威状态，浏览器 IndexedDB 不自动等同于云端数据；导入与同步另做显式流程。至少验证跨租户读取/执行拒绝、撤权、远端断连、任务重启与恢复；现有本机 SQLite 单 owner 模型不能直接宣称支持多 worker。
