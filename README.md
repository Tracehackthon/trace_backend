# Trace

**Trace Runtime · 一个让思考可继续、可带去实践、也可被结果修订的 local-first 工作空间。**

> **把一条还没有想清楚的线索，带过阅读、讨论与实践，再带回自己的判断。**
>
> Trace 是一个 local-first 的思考工作空间：它不把收藏、聊天和任务拆成彼此失联的记录，而是围绕同一件持续变化的事，保存原表达、材料、理解、行动与结果之间的来路。

## 为什么是 Trace

我们不缺保存信息的地方，缺的是让信息在**下一次需要它时仍然有意义**的连接。

- 收藏一篇知乎回答，几周后只剩标题，不记得当时的问题。
- 和 AI 讨论出一点判断，换一个任务又从头解释背景、限制和犹豫。
- 把想法带进一次真实尝试，结果却没有回到原来的理解，下一次仍重复试错。

Trace 的基本单位不是笔记、对话或待办，而是**一件仍在变化的事**。它允许一开始只有一句困惑；材料可以支持、补充或挑战它；理解必须由用户确认；实践结果可以让原来的判断变得更具体，而不是被静态归档。

**Trace 想让评委看到的，不是又一个“AI 搜索 + 笔记”组合，而是一条可被追溯的思考闭环：看见什么、为什么在意、怎样理解、实际试过什么，都围绕同一件事继续演化。**

## 三分钟看懂 Trace

```text
留下一点 ──→ 找个对照 ──→ 说清自己的理解 ──→ 带去用 ──→ 结果回来
     ↑                                                               │
     └──────────────── 同一件事继续变化，而不是另起一份记录 ─────────┘
```

| 时刻 | Trace 做什么 | 不做什么 |
| --- | --- | --- |
| 有触动、疑问或发现 | 保留原表达，创建或回到一件事 | 不逼你立即写总结 |
| 需要更多材料 | 展示来源、摘要与“为什么有关”的关系 | 不把搜索结果自动当成你的结论 |
| 形成判断 | 让你明确保存、修改或保留不确定性 | 不让模型替你改写理解 |
| 准备行动 | 固定本次要带走的内容与上下文 | 不把整库内容无差别发送给工具 |
| 有了结果 | 区分事实、解释和未确认部分，再回看旧判断 | 不把一次结果伪装成永久真理 |

这也是评委可以用来判断 Trace 的标准：**它是否帮助一条内容在后续的选择中被重新使用，而不是只增加一个信息入口。**

## 知乎在 Trace 里不是一个搜索框

知乎为 Trace 提供的是“真实经验与公共讨论”这一层来源，而不只是一个检索按钮。当前本机实现把它放在三条清晰、彼此隔离的路径中：

| 路径 | 用户获得什么 | Trace 保证什么 |
| --- | --- | --- |
| **知乎搜索** | 围绕当前问题寻找社区经验、观点和原始链接 | 只展示接口返回的标题、作者、摘要与真实 URL；不补造正文或链接 |
| **全网搜索** | 用外部资料补充或反驳一条判断 | 与知乎搜索使用不同固定路由，可带受限筛选；结果仍以来源摘要呈现 |
| **用户授权** | 用户主动连接知乎后，按需读取自己的公开内容或近期收藏 | OAuth 与公共搜索分离；不自动读取、翻页、保存或把开发者账号当作用户账号 |
| **Trace Agent 检索** | 在一次明确许可的 Agent 请求中，让模型查找知乎／全网材料 | 每次 run 显式开启、次数与条数受限；来源由宿主登记并校验引文，模型不能伪造来源 |

这四条路径对应四个本机 API 域：

```text
/api/product/*  ─── 事项、理解、确认后的产品状态
/api/search/*   ─── 知乎搜索与全网搜索（公共内容）
/api/zhihu/*    ─── 知乎 OAuth、连接状态、授权后的用户数据
/api/agent/*    ─── 受控生成、来源工具、运行事件与取消
```

搜索结果目前停在“可阅读、可判断是否相关”的摘要层。下一步是让用户**选择一个片段、说明关系、确认后**才关联到当前事项；Trace 不把展示过的内容冒充成已经被吸收的理解。

> 想了解 OAuth、数据边界、环境变量和回调部署，请阅读 [知乎与全网接入](docs/zhihu-native.md)。

## 已实现什么，仍缺什么

### 已实现并可在源码本机路径验证

- **完整的产品状态边界**：SQLite 产品命令、revision CAS、幂等回放、显式保存与结果回流，不接受浏览器整份状态覆盖。
- **可插拔 Agent Runtime**：同一份请求协议可使用本机 Codex、受限模型接口或完整外部 Agent；有 profile、SSE、取消、超时、过期保护和独立 `agent.sqlite` 运行记录。
- **知乎／全网 source provider**：公共搜索、固定来源路由、摘要规范化、限流／取消处理、MCP 工具、可选 Agent 检索和本机 OAuth 协议。
- **Codex 工作往返**：Trace 可以把用户确认的工作快照交给原生 Codex，接收真实结果到待复核区；回传不会自动改变“我的理解”。
- **本机 Web**：围绕“留下一点、从这里接着、找个对照、我的理解、带去用、结果回来”的连续工作流；知乎面板显示真实 provider 摘要，不使用演示结果兜底。

### 诚实的当前边界

| 还未完成 | 这意味着什么 |
| --- | --- |
| 真实 OAuth 线上回调验收 | 登记域名目前还需部署长驻 callback relay；不能把静态页面返回当作授权成功 |
| Agent 回答的完整 Web 交互 | 运行 API 已实现，网页端尚未把回答与“确认采纳”做成完整闭环 |
| 搜索片段确认关联 | 当前可搜索、阅读和判断；片段进入事项仍需下一步用户确认流程 |
| 公网多用户服务 | 本仓库的 Web／OAuth 路径是单用户、loopback、same-origin 设计，不是云端租户系统 |
| 发行与运维闭环 | Web/Agent 打包、备份恢复、运行归档和安全远程连接仍在生产化计划中 |

真实知乎搜索和本机 Web 展示已做过验收；全网端点已连通，但非知乎站点的覆盖仍不应被夸大。完整验证证据与未完成项见 [知乎接入文档](docs/zhihu-native.md#验证与尚未完成)。

## 架构与边界

```text
                           ┌─────────────────────────────────────┐
                           │            Trace Web                │
                           │  一件事 / 材料 / 理解 / 工作现场     │
                           └──────────────┬──────────────────────┘
                                          │ same-origin, loopback
         ┌────────────────────────────────┼────────────────────────────────┐
         │                                │                                │
 /api/product/*                    /api/search/*                    /api/agent/*
 产品命令与 SQLite                  ZhihuProvider                    AgentService
 revision / 回执                    知乎 / 全网摘要                  profile / SSE / 取消
         │                                │                                │
     web.sqlite                 /api/zhihu/*                    agent.sqlite
                                OAuth / 用户数据                 候选与运行账本
                                         │                                │
                                  本机 MCP / Codex  ←─────────────┘
```

设计上的关键不是“所有东西都能连”，而是责任不混在一起：

- **产品库**只保存用户明确确认的内容；搜索、模型和 Agent 不能绕过它写入。
- **来源 provider**处理鉴权、限流、摘要规范化与真实链接；它不是模型 provider。
- **Agent**只能在本次请求明确授予的上下文、来源和工具预算中工作；不能自行打开 shell、任意 URL、文件或知乎用户数据。
- **凭证与浏览器隔离**：Access Secret、App Key、OAuth Token 不进入 MCP 工具输入、模型上下文、产品库或浏览器 JavaScript。

更完整的职责、数据 owner 和远程化缺口在 [底层架构](docs/architecture.md)。

## 本机跑起来

> 本节面向源码贡献者和评委的本机演示。需要 **Node >= 22.13**；本机验证使用 Node 22.23.1。

```sh
npm start
```

终端会输出本机地址（默认 `http://127.0.0.1:4173`）与实际 SQLite 路径。打开后可以直接体验产品的手工闭环；按 `Ctrl+C` 只停止自己启动的服务。

### 体验知乎／全网面板

1. 按 [知乎接入配置](docs/zhihu-native.md#配置本机服务) 将 Access Secret 安全注入**后端进程环境**，并设置 `TRACE_ZHIHU_ENABLED=1`。
2. 启动 `npm start`，在「个人与设置 → 知乎与全网」输入一个具体问题。
3. 分别切换“知乎”和“全网”，查看标题、作者、摘要与原始链接；这些内容不会自动写入事项。
4. 仅在你明确要读自己的知乎内容时，再配置 OAuth 并由你本人完成浏览器授权。

### 体验 Agent

```sh
npm start -- --agent
```

这只开放本机 Agent API，不会自动调用模型或改变页面内容。可使用默认本机 Codex，或在后端配置受限模型／外部 Agent profile；详见 [Agent profile 与执行器协议](apps/agent/docs/profiles.md)。在某次请求内想启用来源检索，必须显式传入：

```json
{"retrieval":{"sources":["zhihu","global"]}}
```

完整启动检查、端口、数据库与安全停用请看 [本机运行手册](docs/local-runtime.md)。

## 面向评委的演示路线

**建议按这个顺序看，而不是先翻 API：**

1. **从一句话开始**：在 Web 留下一段尚未整理的困惑，进入同一件事。
2. **让它遇到真实世界**：打开「知乎与全网」，用一个具体问题检索，比较社区经验与外部资料摘要。
3. **保留你的判断权**：看见搜索结果不会改变理解；只有你自己保存的内容才进入产品状态。
4. **展示可控的 AI 边界**：查看 `/api/agent/capabilities`，或以一次显式 `retrieval.sources` 请求启动 Agent；观察来源、引用与运行记录分别存在独立边界。
5. **回到产品目标**：无论是资料、Agent 回答还是 Codex 工作结果，最终都应回到“这件事接下来如何改变”，而不是多出一条孤立的聊天记录。

## 开发与贡献

```sh
corepack pnpm build
node --test tests/zhihu-native.test.mjs tests/agent-retrieval.test.mjs tests/agent-backend.test.mjs
```

`pnpm build` 编译 CLI/MCP runtime 并检查 TypeScript；它不代表 Web/Agent 已被打包为生产发行物。变更接口、来源或运行边界时，请同时更新对应文档与定向测试；不要把密钥、Token、真实用户内容或本地 `artifacts/` 证据提交到仓库。

---

Trace 的目标不是替人更快地下结论，而是让一条重要但尚未完成的想法，在真实材料与真实行动之后，仍然能够被好好地继续。
