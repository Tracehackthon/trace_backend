# Trace Artifact Lifecycle

**状态：第一阶段范围与安全不变量；不是删除实现或已发布 API。**

## 实施进度

- 已新增桌面端只读盘点模块 `apps/desktop/src/artifacts/artifact-lifecycle.mjs`，以及聚焦测试 `apps/desktop/tests/artifact-lifecycle.test.mjs`。它只读取明确传入的 `.trace/` 和 Runtime 版本根目录的目录项/文件元数据，不读取文件内容、不写入、不移动、不删除；每条当前只开放 `inspect`。
- 该模块尚未接入桌面路由/界面；Runtime 当前版本名由调用方从权威配置提供，不由模块猜测。它是实现切片，不代表桌面管理体验已完成。
- 聚焦测试覆盖未知文件 fail-closed、数据库家族分组、采用收据保护、缺失/未初始化边界、条目数上限及 Runtime 当前/旧版/备份分类。

## 要解决的问题

Trace 桌面端需要让用户看懂 Trace 自己创建、管理或暂存的文件：它是什么、归谁所有、为什么保留、是否有引用、现在能做什么。目标不是把“看起来旧、名字杂、扩展名是 JSON”的文件自动删掉。

## 已确认范围

只纳入两个由 Trace 明确管理的资源域：

1. 用户明确选定项目下的 `.trace/` 项目状态与 Trace 生成物。
2. Trace 管理器登记的 Runtime 版本目录及其回滚副本。

首版明确排除：普通项目文件、Git worktree、来源仓库/开发 checkout、未证明归 Trace 管理的插件缓存、Wiki/认知来源，以及任何 SQLite 数据库内容。`*.sqlite`、`*-shm`、`*-wal`、owner 文件须作为一个受数据库所有者保护的整体处理，不能被通用文件回收器移动或删除。

## 安全不变量

- **先证明归属，再允许动作**：没有 Trace 管理清单、明确受管根目录或可核验来源的条目只能显示为“待确认”；不能因路径、扩展名或时间戳自动取得删除资格。
- **引用优先于年龄**：先从权威配置、项目描述符、收据、任务记录和其他受管清单标记当前根与依赖；旧但仍被引用的资源必须保留。
- **当前与回滚保护**：当前使用中的 Runtime、唯一可恢复副本、未知是否正在使用的版本均不可清理。版本号本身不能证明哪个版本“最新可用”或“稳定”。
- **未知默认保留**：读不懂的清单、路径越界、符号链接、校验失败、并发占用、引用不完整，均降级为只读说明，不继续操作。
- **删除前可恢复**：生命周期顺序为 `盘点/解释 → dry-run 候选 → 可恢复隔离 → 用户确认后永久清除`。隔离须有事务记录、内容校验、原路径和恢复冲突检查；永久清除另设明确确认，不与扫描或隔离合并。
- **不扫描数据库内部来猜清理目标**：本功能第一阶段不做 SQLite 行级清理，也不借用 Agent Run 或 Product Workspace 数据库保存回收器状态。持久化位置须等确认 Runtime/Host 的权威所有者后再定。

## 生命周期模型（用户可见语义）

| 状态 | 含义 | 允许动作 |
| --- | --- | --- |
| `active` | 当前配置或有效引用明确使用 | 查看；禁止隔离/清除 |
| `retained` | 有明确保留理由，如状态库、采用收据、回滚副本或验收证据 | 查看；只有所有者规则允许时才可提出后续处置 |
| `review` | 归属、引用或用途证据不足 | 查看来源/证据；不提供自动清理 |
| `quarantined` | 已按用户确认进入可恢复隔离区 | 查看、校验、恢复；永久清除需新的显式确认 |
| `purgeable` | 引用闭包、所有权、恢复副本及占用检查均通过的候选 | 仅展示 dry-run 结果；不能后台自动执行 |

`purgeable` 是一次扫描计算出的资格，不是写入文件后就永久有效的属性；实际处置时须重新检查。

## 架构边界

把能力放在 Trace 桌面端可调用的 **Artifact Lifecycle Module**，而不是通用“清理临时文件”脚本：

- `ProjectTraceArtifactAdapter`：只枚举用户选择项目根下的 `.trace/`；按 Trace 已知格式解释收据/评估证据，不打开 SQLite 内容。
- `ManagedRuntimeAdapter`：从 Runtime 管理器的权威配置/清单取得受管根、当前版本、回滚关系和占用证据；不从目录名猜测所有权。
- `ReferenceMarker`：沿权威引用标记活动和保留项；不把搜索不到文本引用当作“确定无引用”。
- `LifecycleCoordinator`：汇总解释、dry-run、隔离/恢复和清除事务；UI 展示“是什么/谁创建/为何保留/为何候选/影响/恢复方式”。

第一阶段只交付只读盘点和可解释的 dry-run。模块的持久化接口/具体数据库归属暂不预设，避免把操作日志错误写进 Product 或 Agent 数据域。

## 分阶段执行与验收

1. **范围与基线（本阶段）**：列清受管根、不可触碰项和现存对象类别；不移动、不删除、不创建回收器状态。
2. **只读盘点**：对桌面端显式选定的项目/Runtime 根生成稳定条目 ID、用途说明、所有者证据、引用证据、保护原因和不确定性；默认不计算“删除建议”。
3. **dry-run**：只有所有权已证明且引用标记闭包完整的终态生成物才可成为隔离候选；用合成夹具验证越界路径、未知文件、DB/WAL、当前版本、回滚版本均 fail-closed。
4. **隔离与恢复**：实现原子、可回滚事务；在真实用户目录验证前，先用独立临时目录和故障注入覆盖中断/重名/校验失败。
5. **永久清除**：单独操作、再次核验、逐项解释并要求用户明确确认；保留可审计结果。

首版通过条件：桌面端能解释每个受管条目；未知资源只标记待确认；任何扫描/预览都不写入、不移动、不删除；数据库家族、活跃 Runtime、回滚关系和用户项目边界均有测试保护。
