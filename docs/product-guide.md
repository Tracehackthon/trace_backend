# Trace 产品介绍与使用

> 本文保留产品定位、知乎材料用途和完整使用流程；技术与启动入口已收敛到[仓库 README](../README.md)。启动、安装和工程命令按任务链接读取，不是使用产品的前置课程。

### 把此刻的一点，带到以后。

**Trace 是一个让思考在阅读、讨论和实践之间持续生长的个人工作空间。** 留下一段触动、一个没想清楚的问题，或工作中的发现；下次从这里接着，形成自己的理解，带去真实工作，再让结果回来。

不必先整理好，不必每次重新解释，也不必把一次想法立刻变成结论。

## 为什么做 Trace

我们并不缺少保存信息的地方，缺少的是把它继续用下去的连接。

- **阅读时**，收藏了一篇知乎回答或文章，却忘了当时为什么在意它。
- **讨论时**，和 AI 一起分清了一些问题，换个对话又要从头解释。
- **工作时**，想把已有的判断带进方案、代码或原型，却只能重新拼一段 prompt。
- **实践后**，发现原来的想法只在某些条件下成立，结果却没有回到原来的理解里。

Trace 围绕的不是一条笔记或一次聊天，而是**一件仍在变化的事**。原话、材料、未决问题、自己的理解和实际结果，都可以留在这件事里，彼此接得上。

比如“收藏之后为什么还是用不起来？”可以从一句困惑开始，后来遇到一个反例，形成一个新的判断，再带到一次产品尝试里。事情可以继续变化，不需要被过早归档为“已经想清楚”。

## 你可以用 Trace 做什么

六个动作，连接同一件事。你可以从任何一个动作开始，不必走完一套流程。

| 核心功能 | 什么时候用 | 当前可以怎样做 |
| --- | --- | --- |
| **留下一点** | 有一点触动、疑问或发现，不想现在整理 | 在首页写一句或贴一段，保留原表达，创建一件事 |
| **从这里接着** | 回来时想认出当时在意什么、停在哪里 | 从首页、全部或搜索进入同一件事，回看并继续补写 |
| **找个对照** | 想知道一份材料补充、挑战或限制了哪一处 | 从原表达或理解出发，手工粘贴材料、说明关系、确认关联；也可以不采用 |
| **我的理解** | 想留下自己的表达，而不只是收藏别人的回答 | 自己写、明确保存、继续修订；关联材料不会自动重写理解 |
| **带去用** | 想把已经分清的部分带到当前工作，也可能只是试一次 | 选择本次内容和使用方式，确认工具、项目、任务，保留当时的工作快照 |
| **结果回来** | 试过之后，想让真实结果参与下一次判断 | 分开记录事实、解释和未确认部分；只留下结果，或查看差异后确认修订理解 |

```text
留下一点 → 从这里接着 → 找个对照 → 我的理解
                                      ↓
                                   带去用
                                      ↓
                                  结果回来
                                      ↓
                         回到同一件事，继续修订与尝试
```

搜索、全部痕迹和工作现场不是另外几份副本：它们让你从不同入口回到同一件事。你也可以只留下一点就离开，或只回来看看，不需要每次产出总结。

## 知乎内容在 Trace 中怎么用

**知乎内容不只是 Trace 的搜索来源，而是让一件正在形成的事遇到真实经验、不同条件和不同判断的材料。** 我们希望读过的回答不止停在收藏夹里，而能进入自己的理解和实践。

在这条产品链里，知乎回答、文章与创作者经验有四个具体用途：

| 用途 | 用户正在做什么 | 知乎内容应当怎样参与 |
| --- | --- | --- |
| **从阅读留下一点** | 看到一段有触动的回答，想保留当时为什么在意 | 将选中的片段与自己的原话留在一起，并保留标题、作者和原文来路 |
| **为当前问题找个对照** | 想看看别人是否遇到过、有没有反例、条件哪里不同 | 围绕当前具体问题查找知乎回答与文章；呈现经验发生的情境，而不只给出相似标题 |
| **形成自己的理解** | 比较别人的经验和自己的处境 | 标出这段内容补充、挑战或限制了哪一处；知乎原文、关系解释和用户理解保持区分 |
| **带去尝试，再带回结果** | 想把一条受到启发的判断用到真实工作中 | 保留它来自哪段知乎内容，把它作为参考或待验证的尝试；实践结果回来后，再修订自己的理解 |

**这是一条明确的产品方向，不是当前网页已经完成的联网能力。** 目前可以手工粘贴自己正在阅读的知乎内容作为材料，但 Web 尚未真实调用知乎接口，也没有从接口结果完成标题、作者、摘要 / 片段和原文链接的渲染与关联。仅在查找范围中出现“知乎公开内容”，不算已经接入。

下一步要打通的最小体验是：

```text
在一件事里选择“找个对照”
  → 围绕当前问题查询知乎真实内容
  → 展示标题、作者、返回的摘要 / 片段、原文链接
  → 用户选择一处，说明它与当前问题的具体关系
  → 确认接到同一件事，之后仍能追溯原文
```

我们不打算用一排知乎热榜或预填内容卡片代替这条链路。接口返回摘要时，应明确标为摘要，不冒充全文；查找失败时，应显示真实状态，不用示例回答伪装结果。知乎内容与用户的关联判断也不会自动升级为“我的理解”。

底层已有 [知乎 HTTP transport](../packages/integration/zhihu-transport/README.md) 和 [候选前例 adapter](../packages/integration/zhihu-precedent/README.md)，但仍需接入 Web 的服务端查询、内容展示与对照保存。自动读取个人收藏和关注不属于当前 Web 能力，后续接入也需要单独授权。

## 第一次怎么用

**建议先用桌面浏览器[打开 Trace](https://trace-portal.vercel.app)，从一个你真的在意的问题开始。** 不需要先安装插件、准备知识库或配置模型。

下面是一条可以亲手走完的体验路径。示例文字只用于说明，不会自动写入你的空间。

1. **留下一句原话。** 在首页输入：“我在知乎收藏了不少回答，但真正做事时还是想不起来。”进入这件事，原话会保留。
2. **写下现在分清的一点。** 在“我的理解”中写：“也许缺少的不是分类，而是当时为什么在意、准备在什么情境里使用。”明确保存；没想清楚的部分可以继续留着。
3. **接一份不同的材料。** 选原表达或理解找对照，手工粘贴一段你已阅读的知乎回答或文章片段，填写材料标题，并在材料上下文中注明作者、来路及适用情境。当前不会自动抓取原文，也不会生成已核验的知乎来源卡片；确认关联，不等于同意材料的结论。
4. **带到一次小尝试。** 选择“带去用”，填写本次工具、项目和任务，确认带入快照。例如：在下一次阅读中，多留一句“我准备在哪用它”。网页版会记录这次尝试，不会替你启动外部 Agent。
5. **带着结果回来。** 记录实际发生的事，再决定只保留结果，还是据此修订自己的理解。工作做完了，不等于原来的判断已经得到验证。
6. **下次继续。** 刷新页面，或从搜索、全部、工作现场重新进入，看看原话、当前理解和结果如何接在一起。

**保存提醒：** 网页版使用当前浏览器、当前站点的 IndexedDB，不是云端账号。换浏览器、换域名不会自动带过去；清除网站数据、关闭隐私窗口或浏览器回收存储可能导致内容丢失。请在左下角个人设置中定期导出 JSON，并自行保管。当前没有导入或跨设备迁移界面。

## 选择你的使用方式

| 方式 | 适合谁 | 如何开始 | 数据在哪里 |
| --- | --- | --- | --- |
| **网页版** | 想先体验、记录和继续自己的思考 | [直接打开 Trace](https://trace-portal.vercel.app) | 当前浏览器的 IndexedDB |
| **本机版** | 希望自己保存数据，或准备连接本机 Codex | 按下方步骤运行本仓库中的 Web 服务 | 本机 `web.sqlite` |
| **Trace for Codex** | 已在 Codex 中做项目，希望带入协作上下文、接回工作结果 | 构建 runtime，安装 `trace-codex` Plugin | 项目 `.trace/`；产品内容保存在本机 Web 库 |

**这三种入口不会自动同步。** 线上网页版不会直接连接你电脑上的 Codex，也不会把浏览器里的内容自动搬进本机数据库。要使用产品与 Codex 的工作往返，请从本机版创建并确认工作。

## 连接 Codex

让 Trace 调用 Codex 生成，使用[Agent 后端](../apps/agent/README.md)，无需安装 Trace Plugin。要在 Codex 中领取工作、上下文并回流，按[插件使用说明](codex-plugin.md)连接。

### 让一项工作往返一次

1. 保持本机 Trace 服务运行，默认地址为 `http://127.0.0.1:4173`。
2. 在本机 Trace 中选择“带去用”：工具填写 `Codex`，项目填写**当前 Codex 项目目录的末级文件夹名**，补充本次任务；确认要带入的内容，排除本次不适用的条目。
3. 在对应项目的 Codex 任务中使用 `$trace-work`。如有多项待接工作，先明确要接哪一项；接收成功后会有绑定当前任务、项目与快照的回执。
4. Codex 在原生工作环境中执行与验证，再把事实、解释、未确认项和产物信息送回 Trace。
5. 回到 Trace 复核结果。你可以只留结果，也可以查看差异后确认修订“我的理解”。

“上下文已接收”不等于“任务已完成”，“结果已送回”也不等于“理解已修订”。明确排除的内容不会交给 Codex，回传不会自动成为你的长期判断。

## 当前可用范围

以下按 **2026-09-15 的产品与源码状态**区分，不把底层接口、交互原型或未来方向写成已经上线的完整体验。

| 能力 | 当前状态与边界 |
| --- | --- |
| **网页内容链路** | 已上线：创建事项、继续书写、手工对照、保存理解、工作快照、手工结果与确认修订、搜索、设置与导出 |
| **本机持久化** | 已实现 SQLite 保存、版本冲突检查、命令重试与回执；与认知运行账本分库 |
| **Codex 协作接入** | 已实现 Plugin、MCP、项目初始化、适配提案、候选审阅与可选 hooks；需在本机安装并显式启用对应能力 |
| **项目上下文 Skill 包** | 已实现任务 / 项目绑定的虚拟 `SKILL.md`；需要已锁定的项目 profile，不读取来源正文、不全局安装 |
| **Trace → Codex 生成** | 本机生成 API 已实现，返回回答或候选；默认关闭、页面未接，不代表网页已有自动 AI 对话 |
| **Codex ↔ Trace 工作往返** | 已实现有限快照领取与结果送回复核，已做隔离往返验证；需要运行包含新接口的本机服务和新插件，不连接线上浏览器库 |
| **认知来源与访问记录** | 已实现来源授权、导航与安全访问记录；实际检索由宿主执行，提供入口不等于已经读取或理解 |
| **案例与能力管理** | 已有候选、显式采用、验证、发布预览和回滚回执等底层能力；不是网页版一键自动生成或发布 Skill |
| **知乎内容** | 已有 HTTP transport、CLI 调用入口与候选前例 adapter；Web 尚未真实调用并渲染知乎内容，当前只能手工贴材料。[具体用途与待接链路](#知乎内容在-trace-中怎么用) |
| **其他宿主** | DeepSeek Harness 保留插件与 UI 探索；不与 Codex 已验证往返混为同一完成状态 |

接下来需要补齐的内容链路是：**知乎真实查询 → 来源内容展示 → 选取片段 → 确认对照 → 回到原事项**。其他待接入能力包括真实模型对话、账号与跨设备同步、导入 / 迁移体验，以及移动端适配和桌面分发。以上不代表已经上线或承诺交付日期；运行中工作的快照失效通知等接续机制也仍需完善。

## 你的内容，由你决定怎样留下和使用

- **保存不是采用。** 留下一段材料、建立一个关联或收到一个工作结果，不会自动变成“我的理解”。
- **本次使用不是长期规则。** 一条内容可以是参考、试验或对照；个人判断不会静默升级为项目或团队要求。
- **看得见变化。** 提案、确认与执行结果分开；理解的新修订不会覆盖工作当时保留的旧快照。已经开始的工作也不会自动按新理解重做。
- **来源有范围。** Codex 在用户配置授权与宿主权限内读取资料；来源记录区分提供、搜索与读取，不记录隐藏推理，也不把入口冒充理解证据。
- **安装和迁移分开。** 更新 runtime 或 Plugin 不自动重写旧项目、profile、来源或 hooks；旧项目升级需要检查与确认。

网页版保存你在页面中输入和确认的内容；本机版将产品内容写入 SQLite。Codex runtime 默认不把完整对话、来源正文、凭证和工具参数通用写入状态库；显式案例保存有单独的选择与确认流程。**连接外部 Agent 后，被你确认带入的内容会交给该宿主，其后续处理同时受宿主配置与服务条款约束**，不应把“Trace 本地保存”理解为“任何内容都不会离开电脑”。

JSON 导出与 SQLite 备份可能包含你的原话、材料与工作结果，请作为自己的数据保管，不要随 Issue 或日志公开上传。备份和恢复见 [维护说明](operations.md)；Web 数据另按 [本机 Web 文档](../apps/desktop/README.md) 所述的独立库处理。

## 常见问题

**Trace 是笔记软件、知识库，还是 AI 聊天？**

它可以保留文字和材料，但重点不是多存一份内容，而是让原表达、当前理解与实践结果接在同一件事上。它不替代知识库，也不重造 Codex 的主聊天和执行能力。

**没有 Codex，也能用吗？**

可以。网页版和本机版都能独立完成手工内容链路。Codex 是可选的工作接入，不是使用 Trace 的前提。

**现在可以直接让 Trace 搜知乎、自动回答吗？**

还不能。当前网页找对照靠手工贴材料，继续思考靠自己的补写和修订；真实模型回复与联网搜索仍在后续接入范围。底层 adapter 已存在，不等于网页按钮已经连接在线服务。

**产品指南与底层 README 有什么区别？**

本文介绍产品用途；[仓库 README](../README.md)负责技术定位与最短启动路径。独立前端在 [trace-portal](https://github.com/Tracehackthon/trace-portal)，本仓库承载本机 Web 与 Agent 接入、状态和协议。使用产品不需要先理解模块内部实现。
